# Resolving Email Quarantine Issues for Amazon SES Outbound Notifications

## Overview

A production email notification system experienced inconsistent email delivery after integrating application alerts with **Amazon Simple 
Email Service (SES)**. While some recipients successfully received email notifications, others did not receive them because the messages 
were automatically quarantined by **Microsoft 365 Defender**.

The issue was investigated by analyzing email authentication results, Amazon SES delivery logs, and Microsoft 365 quarantine reports. The 
root cause was identified as an incomplete **DMARC authentication configuration** for the sending domain.

The issue was resolved by verifying the sending domain in Amazon SES, enabling **DKIM signing**, publishing the required DNS records, and 
configuring the domain as an authenticated SES identity. After DNS propagation, email delivery was successfully restored for all 
recipients.

# Problem Statement

Automated email alerts generated by monitoring scripts were delivered inconsistently.

Observed behavior:

* Some users successfully received email alerts.
* Some Distribution Lists received emails intermittently.
* Other recipients never received the emails.
* No delivery failures or bounce notifications were reported by Amazon SES.
* Amazon SES indicated successful message acceptance and delivery.

# Findings

Amazon SES successfully accepted and transmitted all emails.

No issues were observed in:

* SMTP authentication
* SES sending limits
* Bounce reports
* Complaint reports
* Delivery statistics

However, emails reaching Microsoft 365 were inconsistently processed.

Some messages were delivered successfully, while others were automatically quarantined.

---

# Email Authentication Analysis

Reviewing the Microsoft 365 message headers revealed the following authentication results:

| Authentication           | Status |
| ------------------------ | ------ |
| SPF                      | Pass   |
| DKIM                     | Pass   |
| DMARC                    | Fail   |
| Composite Authentication | Fail   |

Although SPF and DKIM validations were successful, **DMARC authentication failed**, causing Microsoft 365 Defender to classify some 
messages as suspicious and quarantine them.

---

# Root Cause

The sending domain used by Amazon SES had not been fully configured for DMARC authentication.

Because of the missing or incomplete domain authentication configuration:

* SPF validation succeeded.
* DKIM signing succeeded.
* DMARC validation failed.
* Composite Authentication failed.
* Microsoft 365 quarantined messages for some recipients based on email protection policies.

Amazon SES considered the messages successfully delivered because they were accepted by the recipient mail server. The quarantine 
occurred **after delivery**, so no bounce or delivery failure was reported by Amazon SES.

---

# Resolution

The following actions were performed to resolve the issue:

1. Verified the sending domain in Amazon SES.
2. Added the sending domain as an authenticated SES Identity.
3. Enabled Easy DKIM for the domain.
4. Published the required DKIM CNAME records in DNS.
5. Verified DNS propagation.
6. Confirmed domain verification status in Amazon SES.
7. Validated email authentication after DNS updates.
8. Sent multiple test emails to different recipient groups.
9. Confirmed successful inbox delivery without quarantine.

# Technical Learning

Amazon SES delivery success does not necessarily guarantee that recipients will receive emails in their inboxes.

Email authentication is evaluated independently by the receiving mail system. Even when Amazon SES reports successful delivery, recipient 
platforms such as Microsoft 365 may quarantine emails if authentication policies are not fully aligned.

Proper configuration of:

* Verified Domain Identity
* SPF
* DKIM
* DMARC

is essential to ensure consistent email delivery and prevent security filters from quarantining legitimate messages.
